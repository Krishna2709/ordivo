# Data, mathematics, Colab, and tracking research

Retrieved **2026-10-18**. Research only: no dataset agreements accepted, gated files downloaded, account authentication, GPU allocation, paid calls, or W&B uploads performed. Public documentation and upstream source were inspected. This companion supplies evidence for `research_findings.md`; proposed project policies below are not upstream guarantees.

## Decisions supported by the evidence

- Synthetic episodes are the unblocked first benchmark. UCI Car is a permissively licensed classification sanity check. Expedia and MSLR remain optional until their agreements and intended use are cleared.
- Classical vector-normalized TOPSIS must explicitly select that normalization when cross-checking `pymcdm`; the library default is min-max.
- Do not use the fetched `pymcdm` COPRAS source as a mathematical oracle without resolving the discrepancy below. A library name or matching rankings is insufficient validation.
- Google's official VS Code Colab extension supports managed Colab notebook kernels. Use that supported OAuth workflow or browser Colab; there is no need for an exposed Jupyter endpoint or tunnel.
- Default experiment logging to genuine W&B offline mode with explicit file allowlists. Sync is a separate user action after reviewing collected files and project visibility.

## Mathematical conventions and cross-checks

Let `X[i,j]` be alternatives by criteria, nonnegative weights sum to one, and criterion directions be explicit. The first positive-domain synthetic generator should use strictly positive finite measurements. Separate score order, ties, and VIKOR compromise admission.

| Method | Formula/convention selected for the project | Preferred order |
| --- | --- | --- |
| COPRAS | `d[i,j] = w[j] X[i,j] / sum_i X[i,j]`; `P[i]` and `C[i]` are sums over benefit and cost columns. For positive cost sums, `Q[i] = P[i] + sum(C)/(C[i] sum(1/C))`. Utility may be reported as `Q/max(Q)` or multiplied by 100; label the scale. | Larger Q |
| WASPAS | Benefit normalization `r = x/max(x)`; cost normalization `r = min(x)/x`. `Q[i] = lambda sum_j(w[j] r[i,j]) + (1-lambda) product_j(r[i,j]**w[j])`, `0 <= lambda <= 1`. | Larger Q |
| VIKOR | Direction-aware regret `d[i,j]=(best[j]-X[i,j])/(best[j]-worst[j])`. `S[i]=sum_j w[j]d[i,j]`; `R[i]=max_j w[j]d[i,j]`; `Q[i]=v(S[i]-min(S))/(max(S)-min(S)) +(1-v)(R[i]-min(R))/(max(R)-min(R))`, `0 <= v <= 1`. | Smaller Q |
| TOPSIS | Vector normalization `r[i,j]=X[i,j]/sqrt(sum_i X[i,j]**2)`; weighted matrix `w*r`; ideal and anti-ideal depend on direction. Euclidean distances `D+`, `D-`; closeness `D-/(D+ + D-)`. | Larger closeness |

The original COPRAS authors' [2007 road-design paper](https://bjrbe-journals.rtu.lv/bjrbe/article/view/1822-427X.2007.4.195%E2%80%93203) is the source for the proportional cost construction. Its public PDF was located, but text extraction was corrupted and rendering/download retrieval was unreliable in this session; **its numerical table has not been transcribed or verified here**. The simplified cost expression above is algebraically equivalent to the standard expression with `min(C)` multiplying the summed numerator and denominator. The WASPAS original paper is [Zavadskas et al., 2012, DOI 10.5755/j01.eee.122.6.1810](https://www.eejournal.ktu.lt/index.php/elt/article/download/1810/1468); its PDF retrieval timed out, so executable convention verification used the maintained library [WASPAS implementation](https://github.com/kotbaton/pymcdm/blob/346a44f5afdac249c534912cc8d483e82586c52d/pymcdm/methods/waspas.py).

VIKOR requires more than a minimum-Q winner: with `m>1`, require `Q(second)-Q(first) >= 1/(m-1)` and that the first alternative also minimize S or R. If only stability fails, the first two form the compromise set; if advantage fails, include the initial alternatives whose gap from the best is below the threshold. Ties and numerical tolerance need explicit handling. [Opricovic and Tzeng, 2004](https://www.sciencedirect.com/science/article/pii/S0377221703000201) distinguishes VIKOR linear normalization from TOPSIS vector normalization; [scikit-criteria's maintained VIKOR documentation](https://scikit-criteria.quatrope.org/en/stable/api/agg/vikor.html) explicitly models the compromise set and warns about degenerate ranges. A unique score minimum is not automatically a unique admissible compromise.

### Library oracle limitations

The [pymcdm API documentation](https://pymcdm.readthedocs.io/en/master/pymcdm.methods.html) uses rows as alternatives, columns as criteria, `types=+1` for benefit and `-1` for cost. WASPAS accepts `l`, VIKOR accepts `v`, and TOPSIS defaults to `minmax_normalization`. For classical TOPSIS, pass `normalizations.vector_normalization`; the library's cost reflection `1-r` is distance-equivalent to direction-aware ideal selection under Euclidean distance. Check **scores** before rankings. VIKOR has opposite score direction from the other three methods.

**COPRAS discrepancy observed in fetched upstream source:** at commit `346a44f5afdac249c534912cc8d483e82586c52d`, [copras.py](https://github.com/kotbaton/pymcdm/blob/346a44f5afdac249c534912cc8d483e82586c52d/pymcdm/methods/copras.py) contains a cost expression equivalent to `P+C`, with no reduction over the alternative cost sums. Public raw-source responses for tags `v1.4.0` (`df8d43705ab6c938104dbf0498d5fa615b067025`) and `v1.3.1` (`906b182b8731a5aae4ab6bf0c45c4f12562a8876`) contained the same expression. This contradicts proportional cost preference. **This is source inspection, not a reproduced installed-wheel result.** Resolve the actual packaged artifact independently, retain its version/hash, and do not change the correct formula to imitate a broken oracle. The source also requires at least one cost criterion and reports utility normalized by max(Q).

A decisive hand case is `X=[[1,1],[1,2]]`, weights `[0.5,0.5]`, directions `[benefit,cost]`: `P=[1/4,1/4]`, `C=[1/6,1/3]`, correct `Q=[7/12,5/12]`, utility `[1,5/7]`. The fetched expression instead gives `[5/12,7/12]`, reversing the cheaper identical-benefit alternative. This calculation is an independent algebraic check, not a package execution claim.

**Independent correct COPRAS implementation located:** [pyDecision/copras.py](https://github.com/Valdecy/pyDecision/blob/07e59ab68bc37bf571211a97ece5685e3adb227a/pyDecision/algorithm/copras.py), pinned commit `07e59ab68bc37bf571211a97ece5685e3adb227a`, computes `s_p + (min(s_m)*sum(s_m))/(s_m*sum(min(s_m)/s_m))`, which retains both required reductions. Call `copras_method(X, weights, ["max", "min"], graph=False, verbose=False)`. With plotting disabled it returns two columns, one-based alternative ID and utility `Q/max(Q)`, in original row order. Its all-benefit path uses `s_p`. This is a suitable independent implementation for positive-domain cross-checks; its source was inspected here, not installed/executed. Do not treat the erroneous pymcdm docstring numbers as a validated published example. The parent implementation audit subsequently reported reproducing the bug in installed `pymcdm==1.3.1`; retain its executable result in the project's ADR/test report.

The pinned [VIKOR source](https://github.com/kotbaton/pymcdm/blob/346a44f5afdac249c534912cc8d483e82586c52d/pymcdm/methods/vikor.py) rejects constant criteria and returns Q without compromise conditions. Cross-check only nondegenerate cases against that oracle. Project-defined handling for all-equal alternatives, zero-weight criteria, zero S/R range, all-benefit COPRAS, and single-alternative episodes must be documented separately. Recommended policy: reject missing/nonfinite values, reject nonpositive WASPAS inputs rather than silently adding epsilon, remove zero-weight dimensions, and make no-information scores explicit ties. Constant VIKOR criteria contribute zero regret as a documented extension. Positive criterion rescaling should preserve these chosen methods; adding alternatives can change normalizers/ideals and rankings, so no blanket independence-of-irrelevant-alternatives claim is justified.

## Dataset eligibility and semantics

### UCI Car Evaluation

[UCI's dataset page](https://archive.ics.uci.edu/dataset/19/car+evaluation) verifies 1,728 rows, six categorical inputs, no missing values, and CC BY 4.0. Inputs are `buying`, `maint`, `doors`, `persons`, `lug_boot`, `safety`; labels are `unacc`, `acc`, `good`, `vgood`. Values include `5more` for doors and `more` for persons, so arbitrary numeric conversion needs justification. Cite Bohanec, *Car Evaluation*, DOI `10.24432/C5JP48`, and preserve attribution. The labels derive from a hierarchical evaluation model; these are neither observed purchases nor hotel query rankings. No download occurred here.

### Expedia Personalized Sort, ICDM 2013

The [official competition data page](https://www.kaggle.com/c/expedia-personalized-sort/data) is visible through the search index although direct browser extraction returned no body. It labels the license as subject to competition rules and requires sign-in/rule acceptance for files. It also prohibits outside data. The [official historical rules PDF](https://storage.googleapis.com/kaggle-media/competitions/kaggle/3504/media/Expedia%20Personalized%20Sort%20Official%20Competition%20Rules%20Final.pdf) includes external-data restrictions and purpose-limited confidentiality obligations; it does **not** establish a general open research license. The current authenticated terms and permission for synthetic-pretrained models, offline research, derived adapters, and publication remain **unverified**. Do not register, accept, download, or upload dataset contents automatically. The historical prohibition matters directly to the proposed MCDM-pretraining transfer experiment; do not claim that a technically downloadable dataset makes that use permissible.

Verified dictionary facts: `srch_id` identifies a search, `prop_id` a property, `random_bool=1` indicates random displayed ordering. Test data omit `position`, `click_bool`, `booking_bool`, and `gross_bookings_usd`. Available features include displayed price, property star/review scores, location scores, stay length, booking window, party size, search context, and competitor signals. `price_usd` conventions vary across countries and may be nightly or full-stay; do not assume a uniform per-night price. No amenity feature was verified. These facts are from the [official data dictionary](https://www.kaggle.com/c/expedia-personalized-sort/data), not third-party copies.

Project inference: retain whole `srch_id` groups when splitting; train click and booking targets separately. Exclude transaction revenue and outcomes from inputs; keep position for bias analysis, not as a serving-available predictor. Random ordering can reduce confounding between the historical ranking policy and item quality, but users still examine higher positions differently. `random_bool=1` is **not** proof that observed labels are unbiased preferences, nor does the dictionary establish known propensities. Validate the randomization unit and candidate-set coverage before any causal claim. Retain raw labels/provenance and declare any combined relevance gain separately.

### MSLR-WEB10K / WEB30K

[Microsoft's official page](https://www.microsoft.com/en-us/research/project/mslr/) describes 136-dimensional query-document features, relevance labels 0–4, `qid` groups, and five predefined query-level folds with three parts for train, one validation, one test. WEB10K samples 10,000 queries; WEB30K has over 30,000. The page explicitly requires reading and accepting an online agreement, whose OneDrive target could not be retrieved here. **License scope remains unknown; no agreement was accepted and no files were downloaded.** Consequently it is a candidate fallback requiring clearance. Preserve whole qids and original folds if used. This is web relevance judgment, not hotel click/booking behavior; transfer conclusions must preserve that domain distinction.

## Scope of the referenced MCDM/LLM paper

[Wang et al., arXiv:2502.15778v1](https://arxiv.org/html/2502.15778v1), dated 2025-02-17, studies supplier evaluation, customer satisfaction, and air-quality assessment using AHP-FCE-related evaluation categories. It compares API prompting and LoRA tuning of Llama3-8B, Qwen2-7B, and ChatGLM4-9B, reporting precision/recall/F1 and high tuned performance. The customer-satisfaction dataset is described as synthetic. This provides motivation for supervised multi-attribute classification; it is not evidence that Liquid d1 implements COPRAS/WASPAS/VIKOR/TOPSIS, reproduces full rankings, generalizes to unseen candidate sets, or predicts hotel choices. Its human-expert-level claim belongs to the authors' task setup and should not become this project's success claim. We have not reproduced its results.

It describes generally up to 12-hour runs and Pro+ continuous execution up to 24 hours with sufficient units; these are not reservations or guaranteed job durations. High-memory settings refer to system RAM. Measure actual GPU/VRAM with `nvidia-smi`, host RAM separately, and record environment/package versions before model loading. The FAQ does not establish the user's actual A100/L4/T4/G4 allocation or cost. Persist checkpoint/config/manifest outside the VM and verify restore. ## W&B offline, artifacts, and privacy

Some `docs.wandb.ai` URLs redirected to inaccessible `docs.coreweave.com` pages during retrieval. The following claims were checked against W&B's own documentation repository at commit `86eefc342c347f15ce6a4cda3114e9daeaccd403`.

- [Offline documentation](https://github.com/wandb/docs/blob/86eefc342c347f15ce6a4cda3114e9daeaccd403/support/models/articles/how-do-i-run-wandb-offline.mdx): `WANDB_MODE=offline` saves metadata locally; confirm `run.settings.mode`; `wandb sync RUN_DIRECTORY` later uploads it. Offline and disabled are different: disabled discards tracking. An offline run is not a cloud run link.
- [Artifact construction](https://github.com/wandb/docs/blob/86eefc342c347f15ce6a4cda3114e9daeaccd403/models/artifacts/construct-an-artifact.mdx): construct `wandb.Artifact(name, type, metadata=...)`, add individually approved files with `add_file`, associate via `run.log_artifact`. Reusing name/type creates versions. Logging is asynchronous; do not infer ordered versions from loop order. Use manifests, configs, reports, and authorized adapters; never add the repo root or raw private dataset directory indiscriminately.
- [Environment controls](https://github.com/wandb/docs/blob/86eefc342c347f15ce6a4cda3114e9daeaccd403/models/track/environment-variables.mdx): `WANDB_CONSOLE=off` disables stdout/stderr capture; `WANDB_DISABLE_CODE=true` prevents notebook/diff capture; `WANDB_DISABLE_GIT=true` prevents git probing. Provide the intended commit explicitly in the allowlisted config. Keep API keys in runtime secrets, never notebook cells or logged config. Offline staging still requires inspection before later sync.
- [Artifact privacy](https://github.com/wandb/docs/blob/86eefc342c347f15ce6a4cda3114e9daeaccd403/models/artifacts/data-privacy-and-compliance.mdx): ordinary artifact logging uploads file contents; project access controls govern visibility. Reference artifacts retain metadata/references instead of copying private bucket contents, but metadata itself can disclose paths. Verify actual project visibility and entity before upload; no default privacy assumption is safe.

The intended first smoke run uses `project="liquid-mcdm-lab"`, offline mode, no cloud authentication, a small safe config and metric, and an allowlisted synthetic manifest artifact. W&B's real offline file output must be tested by implementation; a mock logger alone does not prove this integration. Cloud sync, GPU telemetry, and adapter reload are later runtime checks, not accomplishments of this research.
