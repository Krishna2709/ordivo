# Hugging Face Jobs Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for inline implementation. Workloads and tests execute remotely only.

**Goal:** Prepare one bounded HF Jobs acceptance run, with private durable evidence and no model training.

**Architecture:** Retain pure domain modules. Add HF runtime detection at execution boundaries and share the acceptance pipeline with Colab. A source-only staging tool produces a hash-verified snapshot and explicit launch command; remote bootstrap owns installation and durable logs.

**Tech Stack:** Python standard library for staging/bootstrap, existing hashed CPU lock, HF Jobs Docker CLI and private bucket volumes.

**Spec:** PROJECT_BRIEF.md and the user's selection of Hugging Face Jobs.

## Global constraints

No local workloads, tests, dependency installation, models or generated datasets. Local source editing, packaging and control-plane inspection only. Ask before spending money. No job submission or source upload during preparation. No weights or training in smoke. No .env uploads or secret values in logs. HF Jobs and Colab GPU execution permitted; other/local runtimes rejected.

## Review focus

- Partial HF markers or CPU allocation must fail before installation.
- Skipped tokenizer tests must never yield an acceptance pass.
- Failure/timeout must retain partial logs without claiming success.
- Stale/tampered source staging must be rejected before install.
- Source upload must exclude .env, caches, outputs and credentials.
