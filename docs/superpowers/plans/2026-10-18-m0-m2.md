# Liquid MCDM M0–M2 implementation plan

**Goal:** A verified CPU mathematics/data/tracking pipeline with controlled Colab entry points.
**Spec:** `PROJECT_BRIEF.md`, especially immediate first task and M0–M2 acceptance.
**Architecture:** Pure NumPy solver domain; immutable solver results; JSON episode boundary; deterministic generation and manifest persistence; optional tracking and model compatibility adapters. GPU dependencies are separate from the CPU installation.
**Execution:** Native incremental implementation with failing behavioral tests first, then a fresh independent review. The user has already instructed implementation; no new design approval is required for this bounded scope. No Git metadata exists; do not manufacture commits or a remote.

## Constraints
- Never read keys into output, download model weights, access gated datasets, or launch GPU training.
- Validate primary sources before selecting model/trainer interfaces.
- Exact means documented floating-point formula evaluation, not symbolic arithmetic.
- Keep original brief and `.env` unchanged; user subsequently authorized de01.ipynb as the Colab entry.
- Source measurements and targets retain full precision. No artificial winner for ties or failed VIKOR compromise conditions.

## Alternatives and decisions
1. Generic causal-LM SFT is insufficient unless upstream notebook supports it; choose the verified Liquid TRL path, retain Unsloth as optional pending runtime checks.
2. Runtime dependency on an external MCDM library would obscure conventions. Implement transparent formulas and use a pinned independent library in tests only.
3. A single monolithic notebook prevents ordinary CPU verification. Choose an importable package and thin notebooks.

## Review focus
- Zero/negative values, zero weights, zero variance, invalid shapes, NaN and infinity.
- VIKOR score minimization differs from a unique compromise winner.
- Split scenario families before augmentation; never label rounded prompts with a different teacher problem.
- Offline W&B must not log environment, credentials, raw external data or source snapshots.
- Colab/TRL compatibility remains unproven until the actual loader and loss are exercised on measured hardware.
