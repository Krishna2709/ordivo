# Predeclared bounded Expedia baseline

The official Expedia Personalized Sort labeled training file produced 399,344 complete exposed-search groups and 9,917,530 candidate rows. The remote pod has a 49,999,998,976-byte cgroup memory limit. The baseline runner materializes all four episode splits plus test controls and flattened LightGBM matrices, so the full corpus is outside the credible memory budget for this run. This protocol produces an **exploratory bounded research benchmark**, not an estimate over every source search.

`configs/behavioral/expedia_bounded_sample.yaml` freezes seed 42 and complete-search caps: train 20,000, model-selection validation 2,000, unused calibration 2,000, and test 5,000. The sampler scans and hashes every byte of all four original split files, checks their manifest episode/candidate counts, source-bound IDs and group disjointness, then selects the smallest SHA-256 values of `seed|source|split|episode_id` within each split. Click, booking, features, exposure, candidate order and availability never enter selection. Each selected JSONL episode is copied in full. The derived manifest records parent manifest/split/source hashes, selection config hash, selected ID-set hashes, full/selected/excluded group and candidate counts, selected split hashes, source terms and source pool scope. No data are moved between train, validation, calibration and test.

The existing `configs/behavioral/expedia_lambdarank.yaml` is then fit on the derived four-way manifest. It declares `combined_click_booking_relevance` and the research 0/1/5 LambdaRank target; click and booking remain separate evaluation endpoints. It is not an exactly-one-booking conditional choice probability model, and no temperature calibration is performed. Full prediction coverage means every candidate in every **selected** test search; the aggregate must disclose the full-source and selected denominators, including the excluded unsampled searches. No hyperparameter, cap, or sampling seed is chosen from the selected test metrics.

Operations runs the remote guarded sampler and benchmark from verified source archives after current GPU tasks, writes only under `/workspace`, retains complete per-query files privately, and reads back the small sanitized manifests/aggregates with hashes. Any run failure or change of the predeclared caps requires a new receipt and scope statement. The full source split remains untouched.
