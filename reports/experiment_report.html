Can a decision model learn four exact decision rules?

A 25-step LoRA experiment taught LiquidAI/d1-3B to imitate COPRAS, WASPAS, VIKOR and TOPSIS winners on synthetic multi-criteria choices. It produced a clear learning signal, a small held-out gain, and one unresolved reload failure.

Learning signal confirmed.

Training accuracy rose 39.1 percentage points. This is an overfit check on 64 examples, not evidence of broad generalization or human preference modeling. Release readiness is blocked by probability reload drift.

The experiment

The task is single-choice winner prediction. An exact numerical solver creates a teacher label from an alternatives-by-criteria matrix, criterion weights and directions, and a named MCDM method. The model sees that decision state and must select the winning option alias.

Decision episode

3–8 alternatives, 2–6 criteria, min/max directions and weights.

Exact solver

Deterministic float64 COPRAS, WASPAS, VIKOR or TOPSIS scores.

d1 prompt

Method, parameters, full-precision values and candidate aliases A–Z.

LoRA update

Completion-only loss on the correct answer alias plus EOS.

Choice readout

Restricted option probabilities; argmax compared with the exact teacher.

Dataset

Synthetic MCDM Episodes v1 contains 1,000 reproducible, non-personal examples. It tests mathematical imitation under controlled scenario shifts. It contains no hotel bookings, procurement records or human preference labels.

Every episode stores the method, parameters, weights, directions, matrix, ordered tie groups, raw solver scores and a nullable winner. Nonunique outcomes remain available for analysis but are excluded from single-choice training. Positive-valued inputs are required for COPRAS and WASPAS.

Four teachers

Each method answers a different mathematical question. Their scores cannot be compared across methods, and adding an alternative can change normalizers, ideals and rankings. Use the tabs to inspect each solver contract.

COPRAS

Balances the sum of weighted benefit criteria with an inverse proportional cost term.

Higher Q is better.

Normalize each column by its sum → weight → split benefit P and cost C
Qᵢ = Pᵢ + ΣC / (Cᵢ · Σ(1/C))

Alternative A has twice the benefit and half the cost of B; both criteria have weight 0.5. All four exact solvers select A under their documented conventions.

Failures are evidence

The final run completed training and saved the adapter, then correctly failed its strict validation. Earlier setup failures also narrowed the supported environment. None should be hidden behind the improved headline metric.

Resolved for this run Optional torchao broke the measured stack

The notebook's open-ended torchao>0.16 selected 0.18.0, which failed with Torch 2.9.1. Version 0.15 imported, but PEFT 0.21.2 required 0.16 or newer during LoRA injection.

Resolution: omit optional torchao and use the successful non-quantized BF16 path. TRL 1.15's warmup API was also mapped from the configured 0.05 fraction.

Open blocker Reloaded probabilities drifted

All 4 reloaded predictions kept the same argmax, yet the maximum absolute probability delta was 0.03060 and the mean was 0.00842. Both exceeded the strict 0.0001 threshold.

RuntimeError: Saved adapter reload parity failed

Needs isolation Two loader paths were not identical

The custom d1 wrapper and the standard image-text loader agreed on 7 of 8 base argmax decisions. Their maximum probability delta was 0.01562.

Implication: the evaluation path itself can move a borderline decision. Use one pinned path for comparisons and diagnose dtype, cache, tokenizer and construction differences.

Statistical limitation The test set is too small for tuning decisions

Only 16 held-out examples were evaluated: two VIKOR examples, four TOPSIS examples, and five each for COPRAS and WASPAS. A single prediction can move a method metric by 20–50 percentage points.

Implication: do not tune hyperparameters against these four method percentages. Expand a frozen validation set first.

Weights & Biases was used, but “everything” would overstate the evidence. The run logged offline on the pod and was then explicitly synced to the cloud.

Next experiment

Fix measurement reliability before spending on a larger sweep. Then move from the 64-example diagnostic to a validation-driven 1,000-example run with predictions preserved at episode level.

Close the parity gap

Reproduce save/reload from the same local model snapshot, evaluation mode, dtype, device map and tokenizer. Compare logits before softmax and adapter state hashes. Treat cache settings separately; the recorded use_cache=false check did not remove the drift.

Improve the evidence

Freeze a larger validation split balanced by method, size and family. Persist one row per episode: source hash, teacher scores, exact winner, prompt hash, option probabilities, prediction, correctness and latency. Log the rows as a W&B Table.

Run a bounded comparison

Train on the 800-example split and select on the 100-example validation split. Compare learning rates 1×10⁻⁴ and 2×10⁻⁴ with the same rank-16 LoRA, fixed batch semantics and at least three seeds. Touch the 100-example test split only after selection.

Release criterion: deterministic adapter reload within a justified tolerance, complete per-episode evaluation artifacts, performance reported with denominators and uncertainty, and a model card that preserves the LFM Open License conditions. Exact solvers remain the correct tool for computing the formulas; the learned model is an imitation experiment.
